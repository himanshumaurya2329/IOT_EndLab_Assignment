IoTShield: SDN-Based ARP Spoofing Detection and Man-in-the-Middle Attack Prevention in IoT Networks

Target: Ubuntu on WSL 2 • OpenFlow 1.3 • Ryu Controller • Mininet • Open vSwitch • Flask

1. Technology Stack & Purpose of Each Tool

The project follows an SDN architecture strictly separating the Control Plane (intelligence) and Data Plane (wire-speed switching):

Technology Domain Purpose in IoTShield
Python 3.12 Language Underpins the Ryu controller application, Flask API, Scapy attack script, and automated tests.
Ryu SDN Controller Control Plane Event-driven OpenFlow controller. Inspects ARP/ICMP packets, validates truth table, and issues flow rules.
Open vSwitch (OVS) Data Plane Software virtual switch running in the Linux kernel. Executes forwarding and hardware drop rules at wire-speed.
Mininet (2.3.0) Network Emulator Creates the virtual IoT topology (h1, h2, h3, s1) using native Linux network namespaces and virtual ethernet links.
OpenFlow 1.3 SDN Protocol Standardized protocol connecting OVS and Ryu over TCP port 6633 for Packet-In and Flow-Mod messages.
Scapy (2.5.0) Packet Crafting Generates controlled, customized spoofed ARP replies inside the attacker namespace for realistic attack demo.
Flask & SSE Backend Server Tails the controller event log and pushes real-time events to the web browser over Server-Sent Events (SSE).
SVG & Chart.js Frontend UI Renders a live dark-themed SOC dashboard with packet animations and real-time traffic activity charts.
Is Docker used in this project? — NO.
Docker was deliberately avoided because Mininet requires deep Linux kernel capabilities (network namespaces, veth pairs, and Open vSwitch kernel module openvswitch.ko). Running Mininet in Docker requires fragile --privileged container flags. Because this system runs on Ubuntu on WSL 2, native Linux execution provides superior speed, stability, zero container overhead, and direct localhost:5000 browser access.

Terminal Commands to Demonstrate to Evaluator:

  1. Normal Traffic Test: 
    mininet> h1 ping -c 3 h2
    Result: 0% packet loss. Web UI animates green packets h1 → s1 → h2. Terminal 2 & 3 log 🟢 SAFE ICMP.
  2. Launch ARP Spoofing Attack: 
    mininet> h3 python3 attacks/arp_spoof.py --count 10
    Result: Ryu detects MAC mismatch on Port 3. Ryu drops rogue packet and installs hardware DROP rule (priority 200). Terminal 2 & 3 print red alert. Web UI shows 1.2s toast and flags h3 as QUARANTINED.
  3. Verify Attacker Isolation: 
    mininet> h1 ping -c 3 h2
    Result: 0% packet loss. Legitimate IoT communication is completely unaffected while attacker is quarantined.
  4. Instant Reset for Re-Demo: Click "Reset / Clear Data" in the top-right of the Web UI (or run sudo bash scripts/reset_lab.sh). OVS drop rules are cleared, host ARP caches flushed, and UI resets to 0 without restarting Mininet!

4. Hinglish Q&A & Evaluator Viva Doubts Guide

Q1: UI me "Packets Inspected" count ka kya matlab hai?
Ans: Iska matlab hai ki SDN Controller (Ryu) ne kitne packets ko apne paas receive karke security policy check kiya. Isme valid packets (jaise legitimate ARP aur ICMP request) aur attack packets (h3 ke spoofed ARP) dono count hote hain.
Formula: Packets Inspected = Legitimate Packets + Blocked / Attack Packets.
Q2: Jab hum `h1 ping -c 10 h2` karte hain, toh pehli baar count 4 kyun badhta hai aur 10 kyun nahi?
Ans: Yeh SDN ka core separation principle hai:
  • Packet 1 & 2 (ARP Request & Reply): IP se MAC dhoondhne ke liye controller ke paas gaye → Count = 2.
  • Packet 3 & 4 (ICMP Ping #1 Request & Reply): Switch ke paas rule nahi tha, isliye pehla ping controller ke paas gaya → Count = 4. Controller ne switch me forwarding rule daal diya (port 1 ↔ port 2).
  • Baki ke 8 packets kahan gaye? Rule install hone ke baad packets 2 se 10 tak direct OVS switch ke hardware/kernel level par microsecond speed (0.07 ms) par deliver ho gaye! Controller par baar-baar load nahi dala jata.
Q3: Pehle 10 ping ke baad jab dobara ping karte hain, toh count sirf 2 kyun badhta hai?
Ans: Kyunki is baar ARP resolution dobara nahi karni padi. Host h1 ke paas h2 ka MAC address pehle se yaad tha, isliye usne ARP nahi bheja. Switch ka 5s idle_timeout rule expire hone ke baad sirf 1 ICMP Request + 1 ICMP Reply controller ke paas gaye (Count = 2).
Q4: ARP aur ICMP me kya farak hai aur 1 ping bhejne par kya hota hai?
Ans:
  • ARP (Layer 2): Pata dhoondhta hai — IP address se hardware MAC address nikalta hai.
  • ICMP (Layer 3): Message/Ping bhejta hai — Network connectivity test karta hai.
  • 1 Ping par total 4 steps hote hain: Pehle ARP Request → ARP Reply (rasta mil gaya), phir ICMP Echo Request → ICMP Echo Reply (ping successful).
Q5: `idle_timeout = 5 seconds` ka kya matlab hai?
Ans: Yeh switch ka Inactivity Timer hai. Agar lagataar packet aa rahe hain toh rule rehta hai, lekin jaise hi 5 second tak koi packet nahi aata, switch us rule ko automatically delete kar deta hai taaki switch ki memory bache aur agle packet par Controller dobara security re-verify kar sake.
Q6: Agar switch se rule delete ho gaya, toh dobara ARP kyun nahi hota?
Ans: Kyunki Switch ki memory (Flow Table) aur Host ki memory (OS ARP Cache) alag hoti hain. Switch ne rasta bhulaya, lekin host h1 ke Linux OS ki diary me h2 ka MAC address pehle se yaad tha, isliye usne dobara ARP nahi manga.
Q7: Attack block hone ke baad agar evaluator ko dobara attack dikhana ho, toh kya poora project restart karna padega?
Ans: Bilkul nahi! Sirf UI ke top-right me "Reset / Clear Data" button click karein. Yeh OVS switch se drop rules delete karta hai, hosts ka ARP cache flush karta hai, aur counters 0 kar deta hai bina project restart kiye.

5. Core Technical Viva Questions (English)

Q: Why is the drop rule priority 200 while forwarding rules are priority 100?
Ans: OpenFlow switches evaluate flow rules strictly by descending priority. If a drop rule (priority 200) and a forwarding rule (priority 100) both match a packet, the drop rule wins. Security isolation rules must always supersede operational forwarding rules.
Q: What happens if an unknown host connects to the network?
Ans: If an ARP packet arrives with an IP not present in trusted_bindings.json, the controller flags it as ARP_UNKNOWN_SENDER. By default, it logs a warning and does not auto-trust the host, preventing rogue devices from joining unauthenticated.
Q: How does Server-Sent Events (SSE) compare to WebSockets for this lab?
Ans: SSE is a lightweight, unidirectional server-to-browser push protocol running over standard HTTP (text/event-stream). Since security event logs only need to flow from the SDN backend to the browser, SSE provides automatic reconnection, simpler architecture, and zero WebSocket protocol overhead.
